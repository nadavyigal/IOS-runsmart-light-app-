# RunSmart 1.1.8 (33) TestFlight smoke checklist

Run this on a physical iPhone with the **TestFlight** install of 1.1.8 (33), not an Xcode build.
Xcode builds carry Apple Development signing and a Debug configuration, so they do not prove the store binary.
Base checklist: `docs/qa/ios-qa-checklist.md` (Run tracking and Permissions sections). This file adds the 1.1.8-specific checks.

What 1.1.8 changes:
- #151: voice cues send the Supabase bearer token. Web #134 (live 2026-09-27) returns 401 without it, so on 1.1.7 (32) no cue ever plays.
- #150: movement while paused no longer counts toward distance; guest sign-in copy no longer promises Garmin; the PostHog build key is renamed `app_build` to `build_number`.

## Before you start

- [ ] Settings > General > About, or the TestFlight app, shows RunSmart **1.1.8 (33)**.
- [ ] Record the starting battery %: ____
- [ ] Headphones or phone speaker on, media volume up. Voice cues use the playback audio category, so the silent switch does not mute them; the in-app **Coach / Muted** button does.
- [ ] Outdoors, with a GPS fix (the GPS pill is not showing a weak-signal message).

## 1. Signed-in run with a voice cue (the reason for this release)

- [ ] Sign in (Apple or email). Profile shows your account.
- [ ] Run tab > start a run. The live screen's third button reads **Coach** (waveform icon), not **Muted**. If it reads Muted, tap it once.
- [ ] Keep recording without pausing. At about **5:00** of recording, a spoken cue plays.
- [ ] A second cue plays at about **10:00**.
- [ ] Fail condition: no audio at 5:00 with Coach on. Note the time and whether you had signal; this is the 1.1.7 bug.

Cue timing detail: the cue timer restarts on resume. After a pause, the next cue comes 5 minutes after you tap Resume, not at the next multiple of 5 minutes on the clock. That is existing behavior, not a 1.1.8 regression.

## 2. Pause and resume with travel (#150)

- [ ] During the run, note the distance: ____ km. Tap **Pause**.
- [ ] While paused, walk or jog at least **200 m**. The distance on screen does not grow.
- [ ] Tap **Resume**. The distance continues from the paused value; it does **not** jump by the distance you covered while paused.
- [ ] Fail condition: distance jumps by roughly the paused travel on the first update after Resume.

Known and out of scope: the saved route map and km splits can still draw a straight line across the paused gap. Only the distance total is fixed in this build.

## 3. Lock screen and background recording

- [ ] With the run recording, lock the phone for at least **3 minutes** while moving.
- [ ] The Live Activity on the lock screen shows the run and keeps updating.
- [ ] A voice cue plays while locked if a 5-minute mark falls inside the locked window.
- [ ] Unlock. Elapsed time and distance kept counting and match what you covered.
- [ ] Switch to another app for 1 minute, return. The run is still recording.

## 4. Save, relaunch, history

- [ ] Tap **Finish**, confirm, and save the run.
- [ ] The run summary shows distance and time matching the live screen at finish.
- [ ] Force-quit RunSmart (swipe up in the app switcher), then relaunch.
- [ ] The run appears in run history with the same distance and duration.
- [ ] Open the run report. It loads without an error.

## 5. Guest run (no voice cues, by design)

- [ ] Sign out, or use a second device that is not signed in. Continue as guest.
- [ ] The guest sign-in prompt reads: "Record runs with your iPhone, with optional Apple Health sync. Garmin connections are currently unavailable." It no longer offers Garmin.
- [ ] Start a run and record past **5:00**. **No** voice cue plays. This is expected: guests have no Supabase session, and the app skips the request instead of sending one that returns 401.
- [ ] The run records, pauses, resumes and saves normally.

## After the run

- [ ] Ending battery %: ____ (drop over the session: ____ %).
- [ ] No crash during any step. If there was one, note the step; the crash report appears in App Store Connect > TestFlight > Crashes.

## Result

- [ ] PASS: every box above is checked. Submit 1.1.8 (33) for review.
- [ ] FAIL: note the failing step and do not submit.
